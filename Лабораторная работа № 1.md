# Лабораторная работа № 1

**Развёртывание стенда Ubuntu Server 24.04 LTS и установка Asterisk 22.11.0**

## 1. Цель работы

Цель работы – освоить развёртывание виртуального сервера IP-телефонии, установку программной IP-АТС Asterisk из исходного кода и настройку её автоматического запуска.

В ходе лабораторной работы необходимо:

1. Создать виртуальную машину с Ubuntu Server 24.04 LTS в Oracle VM VirtualBox.
2. Настроить виртуальные сети Internal Network, Host-Only и NAT.
3. Назначить статические IP-адреса согласно индивидуальному варианту.
4. Настроить удалённое управление сервером по SSH.
5. Установить системные зависимости и собрать Asterisk 22.11.0 из исходного кода.
6. Подготовить основные модули PJSIP и RTP.
7. Настроить запуск Asterisk от отдельного системного пользователя через systemd.
8. Проверить работу IP-АТС после перезагрузки и восстановить изоляцию учебного стенда.

**Результат работы:** виртуальная машина `ast-a` с Ubuntu Server 24.04 LTS и установленной IP-АТС Asterisk 22.11.0. Сервер должен иметь два постоянных IP-адреса, поддерживать удалённое подключение по SSH и автоматически запускать Asterisk после включения.

## 2. Теоретические сведения

### 2.1. Программная реализация IP-АТС

**IP-АТС (IP-PBX)** – телефонная станция, обеспечивающая установление, обслуживание и завершение телефонных соединений с использованием IP-сетей.

В отличие от традиционной телефонной станции, программная IP-АТС выполняет основные функции с помощью серверного программного обеспечения. В качестве вычислительной платформы может использоваться физический сервер или виртуальная машина.

Asterisk – программная платформа для построения систем IP-телефонии. Она позволяет организовывать регистрацию абонентских устройств, маршрутизацию вызовов, голосовую почту, конференц-связь, запись разговоров и другие телефонные сервисы.

Функциональность Asterisk реализуется с помощью отдельных программных модулей. При сборке из исходного кода можно определить, какие из них будут включены в установленную систему.

Для работы с протоколом SIP в Asterisk 22 используется программный стек **PJSIP**, построенный на библиотеке pjproject. Передача речевых данных обычно выполняется через RTP, а преобразование звука обеспечивается соответствующими кодеками.

### 2.2. Архитектура виртуального стенда

Для лабораторных работ используется виртуальная машина `ast-a` с Ubuntu Server 24.04 LTS.

Виртуализация позволяет создать отдельный сервер, работающий на ресурсах физического компьютера. При этом виртуальная машина имеет собственную операционную систему, сетевые интерфейсы и файловую систему.

Стенд использует три сетевых подключения.

**Internal Network** – внутренняя сеть VirtualBox, предназначенная для взаимодействия между виртуальными телефонными станциями. В данной работе используется сеть `voip-internal`.

**Host-Only** – сеть, обеспечивающая взаимодействие виртуальной машины с физическим компьютером Windows. Она используется для подключения по SSH и передачи файлов по SFTP.

**NAT (Network Address Translation)** – режим сетевого подключения, позволяющий виртуальной машине обращаться к внешним сетевым ресурсам через физический компьютер. В лабораторной работе NAT используется при установке системных пакетов и компонентов Asterisk.

Постоянными подключениями учебного сервера являются Internal Network и Host-Only. После завершения установки Asterisk адаптер NAT отключается.

### 2.3. Установка программного обеспечения из исходного кода

Установка Asterisk из исходного кода состоит из нескольких этапов.

**Установка зависимостей.** Операционная система должна содержать компилятор, инструменты сборки и библиотеки, необходимые для работы программы.

**Конфигурирование.** Сценарий `configure` проверяет программное окружение и определяет доступные возможности сборки.

**Выбор модулей.** Средство `menuselect` позволяет выбрать компоненты Asterisk, которые необходимо скомпилировать.

**Компиляция.** Утилита `make` преобразует исходный код в исполняемые файлы и программные модули.

**Установка.** Команда `make install` размещает собранные файлы в системных каталогах.

После установки Asterisk необходимо настроить права доступа и запуск через систему управления службами **systemd**.

Systemd позволяет запускать серверные приложения при загрузке Ubuntu, контролировать их состояние и изучать сообщения об ошибках.

## 3. Практическая часть

### Часть 3.1. Развёртывание стенда

#### 3.1.1. Создание виртуальной машины

Создайте виртуальную машину `ast-a` в Oracle VM VirtualBox 6.1.50.

##### Шаг 1. Создание виртуальной машины

Откройте VirtualBox и нажмите **«Создать»**.

Укажите следующие параметры:

- Имя виртуальной машины – `ast-a`.
- Тип операционной системы – Linux.
- Версия – Ubuntu (64-bit).
- Оперативная память – 2048 МБ.
- Виртуальные процессоры – 2.
- Тип виртуального диска – VDI.
- Способ выделения памяти диска – динамический.
- Размер виртуального диска – 15 ГБ.

После создания виртуальной машины перейдите в её настройки и проверьте выбранные параметры.

##### Шаг 2. Создание сети Host-Only

В главном окне VirtualBox откройте **«Файл» → «Менеджер сетей хоста»**.

Создайте сетевой интерфейс Host-Only и укажите:

- IPv4-адрес – `192.168.56.1`;
- маска подсети – `255.255.255.0`;
- DHCP-сервер – отключён.

Адрес `192.168.56.1` принадлежит физическому компьютеру Windows. Для виртуальной машины будет назначен отдельный IP-адрес согласно индивидуальному варианту.

##### Шаг 3. Настройка сетевых адаптеров

Выделите виртуальную машину `ast-a` и откройте **«Настроить» → «Сеть»**.

Включите три сетевых адаптера.

Таблица 1 – Конфигурация сетевых адаптеров VirtualBox

| Адаптер | Тип подключения           | Параметры                 |
| :------ | :------------------------ | :------------------------ |
| 1       | Внутренняя сеть           | `voip-internal`           |
| 2       | Виртуальный адаптер хоста | Созданный Host-Only       |
| 3       | NAT                       | Стандартные настройки NAT |

Для каждого адаптера установите флажки **«Включить сетевой адаптер»** и **«Подключить кабель»**.

Запишите MAC-адреса адаптеров. Они понадобятся для определения соответствующих сетевых интерфейсов в Ubuntu.

##### Шаг 4. Установка Ubuntu Server

В настройках виртуальной машины откройте раздел **«Носители»** и подключите ISO-образ Ubuntu Server 24.04 LTS (amd64).

Запустите виртуальную машину и выполните установку операционной системы.

Во время установки:

1. Выберите стандартные параметры Ubuntu Server.
2. Для третьего сетевого интерфейса настройте автоматическое получение IPv4-адреса по DHCP.
3. Для первых двух интерфейсов не назначайте постоянные адреса – они будут настроены отдельно.
4. Установите операционную систему на виртуальный диск.
5. Создайте обычную учётную запись с правами `sudo`.
6. Укажите имя компьютера `ast-a`.
7. Выберите установку OpenSSH Server.
8. Завершите установку, отключите ISO-образ и перезагрузите виртуальную машину.

После перезагрузки войдите под созданной учётной записью.

##### Шаг 5. Первичная проверка Ubuntu

Откройте терминал Ubuntu и выполните команды.

Пример 1 – Проверка операционной системы (Bash)

```bash
cat /etc/os-release
uname -m
hostname
ip -br addr
ip route
```

Проверьте следующие результаты:

- установлена Ubuntu 24.04 LTS;
- архитектура системы – `x86_64`;
- имя сервера – `ast-a`;
- отображаются три сетевых интерфейса;
- третий интерфейс получил адрес по DHCP;
- присутствует маршрут по умолчанию через NAT.

Если третий интерфейс не получил адрес, проверьте его настройки в VirtualBox и конфигурацию Netplan.

#### 3.1.2. Настройка и восстановление IP-адресов

Для учебного стенда необходимо назначить два постоянных статических IP-адреса.

Первый адрес используется в сети Internal Network, второй – в сети Host-Only. Значения выбираются по таблице индивидуальных вариантов из раздела 4.

В Ubuntu Server для настройки сетевых интерфейсов используется **Netplan**.

##### Шаг 1. Определение сетевых интерфейсов

Выполните:

Пример 2 – Проверка сетевых интерфейсов (Bash)

```bash
ip -br link
ip link show
ls /etc/netplan/
```

Сопоставьте MAC-адреса интерфейсов Ubuntu с MAC-адресами сетевых адаптеров VirtualBox.

Определите интерфейсы Internal Network, Host-Only и NAT.

##### Шаг 2. Назначение статических IP-адресов

Создайте файл конфигурации Netplan:

Пример 3 – Открытие файла настройки Netplan (Bash)

```bash
sudo nano /etc/netplan/asterisk-lab.yaml
```

Пример 4 – Конфигурация статических IP-адресов для варианта 7 (YAML)

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    enp0s3:
      dhcp4: false
      addresses: [10.77.7.10/24]
    enp0s8:
      dhcp4: false
      addresses: [192.168.56.27/24]
```

В данном примере виртуальная машина получает:

- `10.77.7.10/24` – для сети Internal Network;
- `192.168.56.27/24` – для сети Host-Only.

Замените IP-адреса на значения своего варианта, а имена интерфейсов – на фактические.

Шлюз по умолчанию для этих двух интерфейсов не указывается. Выход к внешним ресурсам обеспечивается третьим адаптером NAT.

Сохраните файл и установите права доступа:

Пример 5 – Назначение прав доступа к конфигурации Netplan (Bash)

```bash
sudo chmod 600 /etc/netplan/asterisk-lab.yaml
```

##### Шаг 3. Применение настроек

Проверьте конфигурацию и примените изменения.

Пример 6 – Применение Netplan (Bash)

```bash
sudo netplan generate
sudo netplan try
```

Если настройки применились корректно, подтвердите их сохранение клавишей `Enter`.

Проверьте IP-адреса:

Пример 7 – Проверка IP-адресов (Bash)

```bash
ip -br addr
```

Ожидается наличие двух статических адресов своего варианта и адреса NAT-интерфейса.

Проверьте маршрут по умолчанию:

Пример 8 – Проверка маршрутов (Bash)

```bash
ip route
```

Он должен проходить через третий интерфейс.

#### 3.1.3. Настройка SSH-доступа

**SSH** позволяет управлять Ubuntu Server с компьютера Windows через сеть Host-Only.

##### Шаг 1. Проверка SSH

На Ubuntu выполните:

Пример 9 – Запуск SSH-сервера (Bash)

```bash
sudo systemctl enable --now ssh
systemctl is-active ssh
```

Убедитесь, что служба находится в состоянии `active`.

##### Шаг 2. Создание SSH-ключа

На компьютере **Windows** откройте PowerShell.

Пример 10 – Создание SSH-ключа (PowerShell)

```powershell
ssh-keygen -t ed25519
```

Нажмите `Enter`, чтобы сохранить ключ в стандартном расположении. При необходимости задайте парольную фразу.

Если ключ уже существует, используйте его, не перезаписывая.

##### Шаг 3. Передача ключа и подключение

В PowerShell выполните:

Пример 11 – Передача SSH-ключа (PowerShell)

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh user@192.168.56.27 "umask 077; mkdir -p ~/.ssh; cat >> ~/.ssh/authorized_keys"
```

Замените `user` своим именем пользователя Ubuntu, а `192.168.56.27` – адресом Host-Only своего варианта.

При первом подключении убедитесь, что отпечаток ключа SSH-сервера соответствует отпечатку, полученному в локальной консоли Ubuntu командой `sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`. Затем введите пароль пользователя Ubuntu для передачи открытого ключа.

Проверьте подключение:

Пример 12 – Подключение к Ubuntu по SSH (PowerShell)

```powershell
ssh user@192.168.56.27
```

После входа в Ubuntu выполните:

Пример 13 – Проверка имени сервера (Bash)

```bash
hostname
```

Ожидаемый результат – `ast-a`.

После успешной проверки выключите виртуальную машину и создайте снимок VirtualBox **«Сеть и SSH настроены»**.

Затем включите виртуальную машину для выполнения следующей части лабораторной работы.

### Часть 3.2. Сборка и запуск Asterisk 22.11.0

На этом этапе необходимо установить системные зависимости, получить исходный код Asterisk, выполнить компиляцию и настроить запуск IP-АТС.

#### 3.2.1. Установка системных зависимостей

Для сборки Asterisk необходимы компилятор, средства разработки и системные библиотеки.

##### Шаг 1. Проверка сетевого подключения

В Ubuntu выполните:

Пример 14 – Проверка сетевого подключения (Bash)

```bash
ip route
getent hosts downloads.asterisk.org
```

Убедитесь, что маршрут по умолчанию проходит через третий сетевой адаптер и доменное имя `downloads.asterisk.org` разрешается в IP-адрес.

Если проверка не прошла, убедитесь, что NAT-интерфейс получил IPv4-адрес и имеет корректные настройки DHCP и DNS.

##### Шаг 2. Установка необходимых пакетов

Обновите индекс пакетов Ubuntu:

Пример 15 – Обновление индекса пакетов Ubuntu (Bash)

```bash
sudo apt update
```

Установите средства компиляции и библиотеки.

Пример 16 – Установка системных зависимостей (Bash)

```bash
sudo apt install --no-install-recommends --no-remove \
  build-essential wget subversion libjansson-dev \
  libxml2-dev libssl-dev libncurses-dev libnewt-dev \
  libsqlite3-dev libcurl4-openssl-dev libspandsp-dev \
  libsrtp2-dev libyuv-dev libpcap-dev pkg-config \
  libiksemel-dev uuid-dev libedit-dev libgsm1-dev
```

Пакет `build-essential` предоставляет основные инструменты компиляции. Пакеты с окончанием `-dev` содержат файлы, необходимые для сборки программ с использованием соответствующих библиотек.

Параметр `--no-install-recommends` исключает необязательные рекомендуемые пакеты, а `--no-remove` запрещает удаление уже установленных пакетов.

Дождитесь завершения установки без ошибок.

#### 3.2.3. Конфигурирование Asterisk и выбор модулей

**Конфигурирование** подготавливает исходный код к сборке и проверяет доступность необходимых системных библиотек.

##### Шаг 1. Конфигурирование Asterisk

Выполните:

Пример 23 – Конфигурирование Asterisk (Bash)

```bash
./configure \
  --with-pjproject-bundled \
  --with-jansson \
  --without-jansson-bundled \
  --without-libjwt-bundled
```

Параметры команды определяют особенности сборки:

- `--with-pjproject-bundled` – использование bundled pjproject.
- `--with-jansson` – использование библиотеки Jansson.
- `--without-jansson-bundled` – использование системной версии Jansson вместо встроенной.
- `--without-libjwt-bundled` – отключение сборки встроенной библиотеки libjwt.

**pjproject** – библиотека, обеспечивающая работу стека PJSIP. При конфигурировании Asterisk может автоматически загрузить необходимые исходные файлы pjproject.

Дождитесь успешного завершения `configure`.

Если программа сообщает об отсутствии библиотеки, изучите сообщение, установите требуемую зависимость и повторите конфигурирование.

##### Шаг 2. Выбор модулей

Откройте Menuselect:

Пример 24 – Открытие Menuselect (Bash)

```bash
make menuselect
```

Menuselect позволяет выбрать модули, которые будут собраны и установлены вместе с Asterisk.

В меню используются обозначения:

- `[*]` – модуль выбран.
- `[ ]` – модуль не выбран.
- `XXX` – модуль недоступен из-за отсутствующей зависимости.

Проверьте выбор основных модулей.

Таблица 2 – Основные модули Asterisk

| Раздел Menuselect | Модули                                                                                                   |
| :---------------- | :------------------------------------------------------------------------------------------------------- |
| Channel Drivers   | `chan_pjsip`, `chan_iax2`                                                                                |
| Resource Modules  | `res_pjsip`, `res_pjsip_session`, `res_rtp_asterisk`, `res_srtp`                                         |
| Applications      | `app_dial`, `app_echo`, `app_playback`, `app_voicemail`, `app_queue`, `app_confbridge`, `app_mixmonitor` |
| Codec Translators | `codec_ulaw`, `codec_alaw`                                                                               |

Модули PJSIP обеспечивают работу SIP-сигнализации, `res_rtp_asterisk` используется для обработки медиапотоков, а `codec_ulaw` и `codec_alaw` обеспечивают преобразование звука для G.711.

Если нужный модуль недоступен, изучите строку `Depends upon` и устраните отсутствующую зависимость.

Остальные компоненты без необходимости не отключайте.

##### Шаг 3. Настройка звуковых пакетов

В Menuselect откройте категории:

- Core Sound Packages;
- Extras Sound Packages;
- Music On Hold File Packages.

В этих категориях выбираются стандартные звуковые сообщения и музыка ожидания.

Для данной лабораторной работы достаточно стандартного набора звуковых файлов, выбранного по умолчанию. При установке Asterisk необходимые файлы будут загружены автоматически.

Сохраните настройки Menuselect через **Save and Exit**.

#### 3.2.4. Компиляция и установка Asterisk

После успешного конфигурирования и сохранения выбора модулей можно приступать к компиляции.

##### Шаг 1. Компиляция Asterisk

Пример 25 – Сборка Asterisk (Bash)

```bash
make -j2
```

Параметр `-j2` разрешает выполнение двух задач компиляции одновременно. Это соответствует конфигурации виртуальной машины с двумя виртуальными процессорами.

Компиляция может занимать некоторое время и сопровождаться большим количеством сообщений.

При успешном завершении появляется сообщение:

Пример 26 – Ожидаемое сообщение об успешной сборке (Text)

```text
Asterisk Build Complete
```

##### Шаг 2. Установка Asterisk

Выполните:

Пример 27 – Установка Asterisk (Bash)

```bash
sudo make install
sudo make samples
sudo ldconfig
```

`make install` устанавливает исполняемые файлы и программные модули.

`make samples` создаёт примеры конфигурационных файлов в каталоге `/etc/asterisk`. Эту команду необходимо выполнять только при первоначальной установке, поскольку существующие настройки могут быть перезаписаны.

`ldconfig` обновляет кэш разделяемых библиотек.

Проверьте установленную версию:

Пример 28 – Проверка установленной версии Asterisk (Bash)

```bash
asterisk -V
```

Ожидаемая версия – `Asterisk 22.11.0`.

#### 3.2.5. Настройка системного пользователя и автозапуска

Для постоянной работы Asterisk необходимо создать отдельную системную учётную запись и настроить службу systemd.

##### Шаг 1. Создание пользователя Asterisk

Пример 29 – Создание системной учётной записи (Bash)

```bash
getent group asterisk || sudo groupadd --system asterisk

id asterisk || sudo useradd --system \
  -g asterisk -d /var/lib/asterisk \
  -s /usr/sbin/nologin asterisk
```

Пользователь `asterisk` предназначен для запуска серверного процесса с ограниченными правами.

##### Шаг 2. Настройка прав доступа

Создайте каталог кэша и назначьте владельца рабочих каталогов:

Пример 30 – Настройка прав каталогов (Bash)

```bash
sudo mkdir -p /var/cache/asterisk

sudo chown -R asterisk:asterisk \
  /var/log/asterisk /var/lib/asterisk \
  /var/spool/asterisk /var/cache/asterisk

sudo chgrp -R asterisk /etc/asterisk
sudo chmod -R g+rX /etc/asterisk
```

Теперь системный пользователь `asterisk` сможет читать конфигурационные файлы и записывать рабочие данные в предназначенные для этого каталоги.

##### Шаг 3. Настройка Asterisk

Откройте файл:

Пример 31 – Открытие конфигурации Asterisk (Bash)

```bash
sudo nano /etc/asterisk/asterisk.conf
```

Проверьте параметры в существующих разделах `[options]` и `[files]`.

Пример 32 – Настройка системного пользователя (INI)

```ini
[options]
runuser = asterisk
rungroup = asterisk

[files]
astctlpermissions = 0660
astctlowner = asterisk
astctlgroup = asterisk
```

Параметры определяют системную учётную запись и права доступа к управляющему сокету Asterisk.

Изменяйте значения внутри существующих разделов файла, не создавая повторные секции.

##### Шаг 4. Создание службы systemd

Создайте файл службы:

Пример 33 – Создание файла службы systemd (Bash)

```bash
sudo nano /etc/systemd/system/asterisk.service
```

Пример 34 – Конфигурация службы Asterisk (INI)

```ini
[Unit]
Description=Asterisk 22 IP-PBX
After=network.target

[Service]
Type=simple
User=asterisk
Group=asterisk
WorkingDirectory=/var/lib/asterisk
RuntimeDirectory=asterisk
RuntimeDirectoryMode=0750
ExecStart=/usr/sbin/asterisk -f -C /etc/asterisk/asterisk.conf
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

В файле определены системный пользователь, рабочий каталог, команда запуска и условия автоматического перезапуска.

Путь к исполняемому файлу в параметре `ExecStart` должен соответствовать результату команды:

Пример 35 – Определение пути к Asterisk (Bash)

```bash
command -v asterisk
```

##### Шаг 5. Запуск службы

Пример 36 – Запуск Asterisk (Bash)

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now asterisk
```

Проверьте состояние:

Пример 37 – Проверка состояния службы Asterisk (Bash)

```bash
systemctl is-active asterisk
systemctl is-enabled asterisk
```

Ожидаемые значения – `active` и `enabled`.

Если служба не запускается, изучите журнал:

Пример 38 – Просмотр журнала службы Asterisk (Bash)

```bash
sudo journalctl -u asterisk -b -n 50 --no-pager
```

Определите причину ошибки и устраните её перед продолжением работы.

#### 3.2.6. Проверка Asterisk и завершение настройки стенда

##### Шаг 1. Проверка версии и модулей

Пример 39 – Проверка Asterisk (Bash)

```bash
sudo asterisk -rx "core show version"
sudo asterisk -rx "module show like pjsip"
sudo asterisk -rx "module show like res_rtp_asterisk"
```

Первая команда показывает версию запущенного Asterisk.

Вторая выводит загруженные модули PJSIP.

Третья проверяет наличие модуля `res_rtp_asterisk`, необходимого для передачи медиапотоков.

Убедитесь, что версия соответствует `22.11.0`, а основные модули присутствуют в списке.

##### Шаг 2. Отключение NAT

После установки Asterisk выключите виртуальную машину:

Пример 40 – Завершение работы Ubuntu (Bash)

```bash
sudo shutdown -h now
```

В настройках VirtualBox откройте раздел **«Сеть»** и отключите адаптер 3 (NAT).

Адаптеры Internal Network и Host-Only оставьте включёнными.

##### Шаг 3. Проверка после перезагрузки

Запустите виртуальную машину и подключитесь к ней по SSH с компьютера Windows.

Пример 41 – Итоговая проверка (Bash)

```bash
hostname
ip -br addr
ip route

systemctl is-active asterisk
systemctl is-enabled asterisk

sudo asterisk -rx "core show version"
sudo asterisk -rx "module show like pjsip"
```

Убедитесь, что:

1. Имя сервера – `ast-a`.
2. Присутствуют два постоянных IP-адреса своего варианта.
3. Маршрут по умолчанию через NAT отсутствует.
4. Подключение по SSH через Host-Only работает.
5. Служба Asterisk активна и запускается автоматически.
6. Версия программы соответствует `22.11.0`.
7. Основные модули PJSIP загружены.

После проверки выключите виртуальную машину и создайте снимок VirtualBox **«Asterisk установлен»**.

**Результат части 3.2:** установлена IP-АТС Asterisk 22.11.0, настроены необходимые модули PJSIP и автоматический запуск через systemd. Сервер работает в изолированной учебной сети.

## 6. Типичные ошибки и способы устранения

Таблица 5 – Типичные ошибки при развёртывании Asterisk

| Проблема                                    | Возможная причина                                       | Способ устранения                                                                 |
| :------------------------------------------ | :------------------------------------------------------ | :-------------------------------------------------------------------------------- |
| SSH недоступен с Windows                    | Неправильный адрес Host-Only или служба SSH не запущена | Проверить настройки адаптера, IP-адрес и состояние SSH                            |
| Netplan не применяет настройки              | Ошибка YAML или неверное имя интерфейса                 | Проверить файл и MAC-адреса, выполнить `sudo netplan generate`                    |
| Отсутствует сетевое подключение             | NAT, DHCP или DNS настроены неправильно                 | Проверить третий адаптер, `ip route`, адрес и DNS                                 |
| APT не устанавливает пакеты                 | Недоступны репозитории или отсутствует зависимость      | Проверить сообщение APT, использовать приложение А                                |
| Не загружается исходный код                 | Ошибка соединения с сервером загрузки                   | Проверить адрес источника и подключение, использовать приложение А                |
| `configure` не находит pjproject            | Не удалось загрузить необходимый исходный архив         | Использовать локальный кэш по приложению А                                        |
| `make` завершается ошибкой                  | Отсутствует библиотека или недостаточно ресурсов        | Изучить сообщение, устранить причину; при нехватке памяти использовать `make -j1` |
| `make install` не загружает звуковые пакеты | Недоступен источник звуковых файлов                     | Отключить соответствующие пакеты в Menuselect по приложению А                     |
| Asterisk не запускается                     | Ошибка конфигурации, прав или пути к программе          | Проверить `journalctl -u asterisk -b`                                             |
| После перезагрузки служба не работает       | Автозапуск не включён или процесс завершился с ошибкой  | Проверить `systemctl is-enabled`, `systemctl is-active` и журнал                  |

При возникновении ошибки сначала определите её причину по сообщениям программы и системному журналу. После исправления повторите соответствующую проверку.

## Приложение А. Резервная автономная установка Asterisk

Приложение предназначено для установки Asterisk при недоступности сетевых репозиториев или отдельных ресурсов загрузки.

Для выполнения автономной установки преподаватель предоставляет следующие архивы.

Таблица 6 – Комплект файлов для автономной установки

### А.1. Передача файлов с Windows

Откройте WinSCP на компьютере Windows.

Подключитесь к виртуальной машине `ast-a` по протоколу SFTP через сеть Host-Only.

Укажите IP-адрес своего варианта, порт `22` и имя пользователя Ubuntu.

Перенесите необходимые архивы в домашний каталог пользователя.

На Ubuntu выполните:

Пример 42 – Переход в домашний каталог (Bash)

```bash
cd ~
ls -lh
```

Убедитесь, что архивы переданы полностью. Если предоставлены контрольные суммы, проверьте целостность файлов до использования.

### А.2. Установка зависимостей из локального репозитория

Распакуйте архив репозитория:

Пример 43 – Распаковка локального репозитория (Bash)

```bash
sudo tar -xzf ~/asterisk-deps-repo-ubuntu24-amd64.tar.gz -C /opt
```

Запустите скрипт настройки:

Пример 44 – Подключение локального репозитория (Bash)

```bash
sudo bash /opt/asterisk-deps-repo-ubuntu24-amd64/setup-offline.sh
```

Скрипт проверяет файлы репозитория, подключает его к APT и обновляет индекс доступных пакетов.

**Скрипт не устанавливает сами пакеты.**

После подключения репозитория выполните команду установки зависимостей из примера 10 пункта 3.2.1.

При необходимости запретить получение пакетов из удалённых источников добавьте к команде `apt install` параметр `--no-download`.

Если установка завершилась без ошибок, переходите к подготовке исходников Asterisk.

### А.3. Подготовка исходного кода Asterisk

Распакуйте предоставленный архив:

Пример 45 – Распаковка исходного кода Asterisk (Bash)

```bash
cd ~
tar -xzf asterisk-22.11.0.tar.gz
cd asterisk-22.11.0
```

После распаковки исходный код будет находиться в каталоге `~/asterisk-22.11.0`.

### А.4. Подготовка локального кэша pjproject

Для конфигурирования Asterisk используется bundled pjproject. Если библиотека не может быть загружена из внешнего источника, её архив необходимо разместить в локальном кэше.

Создайте каталог и скопируйте архив:

Пример 46 – Подготовка кэша pjproject (Bash)

```bash
mkdir -p ~/asterisk-cache
cp ~/pjproject-2.17.tar.bz2 ~/asterisk-cache/
```

Перейдите в каталог исходного кода Asterisk:

Пример 47 – Переход к исходному коду Asterisk (Bash)

```bash
cd ~/asterisk-22.11.0
```

Выполните конфигурирование с указанием локального кэша:

Пример 48 – Конфигурирование с локальным кэшем (Bash)

```bash
./configure \
  --with-pjproject-bundled \
  --with-download-cache="$HOME/asterisk-cache" \
  --with-jansson \
  --without-jansson-bundled \
  --without-libjwt-bundled
```

Параметр `--with-download-cache` указывает каталог с подготовленными внешними компонентами.

При наличии подходящего архива Asterisk может использовать локальные файлы для сборки bundled pjproject.

Дождитесь успешного завершения конфигурирования.

### А.5. Установка без дополнительных звуковых пакетов

Если установка Asterisk прерывается при загрузке звуковых пакетов, откройте Menuselect:

Пример 49 – Открытие Menuselect для настройки звуковых пакетов (Bash)

```bash
cd ~/asterisk-22.11.0
make menuselect
```

Отключите выбранные пакеты в категориях:

- Core Sound Packages;
- Extras Sound Packages;
- Music On Hold File Packages.

Сохраните изменения через **Save and Exit**.

Выполните сборку и установку:

Пример 50 – Сборка и установка без звуковых пакетов (Bash)

```bash
make -j2
sudo make install
```

Asterisk будет установлен без стандартных голосовых сообщений и музыки ожидания.

При этом приложения `app_playback`, `app_voicemail` и другие компоненты могут оставаться включёнными. Для использования стандартных звуковых сообщений потребуется установить соответствующие файлы отдельно.

После успешной установки продолжите настройку системного пользователя, службы systemd и проверку Asterisk согласно пунктам 3.2.5–3.2.6.

**Результат приложения А:** установка Asterisk с использованием подготовленных локальных компонентов без обязательной загрузки файлов из внешних источников.
