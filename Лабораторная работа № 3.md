# Лабораторная работа № 3

**Сценарии обработки вызовов в Asterisk 22**

## 1. Цель работы

Освоить проектирование, настройку и диагностику телефонных сервисов на базе диалплана Asterisk 22.11.0. Изучить десять механизмов обработки вызовов; реализовать и защитить три взаимосвязанных сценария индивидуального варианта.

## 2. Теоретические сведения

### 2.1. Обработка вызова и диалплан

Диалплан Asterisk описывает контексты, добавочные номера и последовательные приоритеты исполнения. Для вызова телефонов используется Dial(), для переходов — Goto() и GotoIf(), для воспроизведения — Playback() и Background(), для завершения — Hangup(). Обращение к переменным выполняется в форме ${ИМЯ}, к функциям — ${DB(семейство/ключ)}. Контекст [PJSIP endpoint](https://docs.asterisk.org/Configuration/Channel-Drivers/SIP/Configuring-res_pjsip/) задаёт точку входа вызова.

### 2.2. Ввод DTMF и состояние каналов

Background() позволяет воспринимать DTMF во время проигрывания записи, WaitExten() ожидает следующий ввод. Для совместимости софтфона и Asterisk согласуйте `dtmf_mode=rfc4733` ([RFC 4733](https://www.rfc-editor.org/info/rfc4733/)). Для диагностики после Dial() используется переменная DIALSTATUS, например BUSY, NOANSWER и CHANUNAVAIL; наличие регистрации SIP ещё не означает доступность абонента для разговора.

### 2.3. Дополнительные услуги

Голосовая почта сохраняет сообщения при отсутствии ответа, группы вызова оповещают несколько телефонов, очередь распределяет поступающие вызовы между операторами, а конференция соединяет несколько каналов. Парковка временно удерживает уже установленный разговор, перехват предназначен для принятия вызова, ещё не отвеченного другим абонентом. AstDB хранит простые изменяемые настройки, в том числе режим «не беспокоить» (DND).

## 3. Исходные условия

Используйте ВМ ast-a из ЛР № 1: Ubuntu Server 24.04 LTS, Asterisk 22.11.0, PJSIP и VirtualBox Internal Network voip-internal. Адрес внутреннего интерфейса 10.77.v.10/24, Host-Only ВМ 192.168.56.(v+20)/24, где v — вариант 1–30. Это адреса гостевой ОС; адрес Host-Only интерфейса хоста настраивается отдельно.

Должна быть завершена ЛР № 2: не менее двух абонентов с четырёхзначными номерами, успешная регистрация PJSIP и двусторонний разговор. Для очереди и конференции создайте третьего тестового абонента. Сохраните копии конфигураций внутри гостевой ОС и снимок состояния ВМ перед изменениями. Пароли и PIN выбирайте самостоятельно; не включайте их в сдаваемые материалы.

*Пример 1 — проверка исходного состояния (CLI Asterisk)*

```text
core show version
pjsip show endpoints
dialplan show
module show like app_
```

## 4. Практическая часть

### 4.1. Интерактивное голосовое меню (IVR)

Создайте отдельный контекст меню. На свободном служебном номере обеспечьте два варианта DTMF-маршрутизации: вызов абонента и переход к другому сервису. Предусмотрите реакции на неверную цифру i и на отсутствие ввода t; убедитесь, что доступна проигрываемая системная запись.

*Пример 2 — принцип ожидания ввода (extensions.conf)*

```text
[example-ivr]
exten => s,1,Answer()
 same => n,Background(demo-congrats)
 same => n,WaitExten(5)
exten => 1,1,Playback(demo-thanks)
 same => n,Hangup()
exten => i,1,Hangup()
exten => t,1,Hangup()
```

Пример показывает только одну ветку. Настройте два назначения самостоятельно; отдельно проверьте корректный ввод, ошибку и тайм-аут.

### 4.2. Голосовая почта

В voicemail.conf создайте почтовый ящик, задайте отдельный секрет и настройте VoiceMail() при занятости либо отсутствии ответа. Обеспечьте доступ к VoiceMailMain() по защищённому служебному номеру. Сравните режимы u (unavailable) и b (busy), оставьте и прослушайте тестовое сообщение.

*Пример 3 — направление в голосовую почту*

```text
exten => 0991,1,VoiceMail(1101@default,u)
 same => n,Hangup()
```

Для работы примера заранее требуется ящик 1101@default. Номера собственного варианта выберите из свободного диапазона.

### 4.3. Группа вызова

Реализуйте одновременный вызов двух телефонов посредством Dial() с каналами, разделёнными символом &, и последовательный вызов с ограничением времени. Установите, что происходит с другими телефонами после ответа первого.

*Пример 4 — одновременный вызов*

```text
exten => 0992,1,Dial(PJSIP/1101&PJSIP/1102,15)
 same => n,Hangup()
```

Замените номера на действующие endpoint своего стенда; при отсутствии подходящего кодека убедитесь в корректной обработке ошибки.

### 4.4. Очередь вызовов

В queues.conf создайте очередь с двумя участниками, музыкой ожидания и заданной стратегией. В диалплане используйте Queue(), настройте тайм-аут ожидания и действие после выхода. Проверьте работу с доступными и недоступными операторами; исследуйте значение QUEUESTATUS.

*Пример 5 — вызов очереди*

```text
exten => 0993,1,Answer()
 same => n,Queue(lab-support,,,,30)
 same => n,NoOp(QUEUESTATUS=${QUEUESTATUS})
 same => n,Hangup()
```

Очередь lab-support должна быть описана отдельно. Командой queue show проверьте участников и доступность.

### 4.5. Переадресация

Создайте правило перенаправления вызова по состоянию: безусловно, при занятости либо после отсутствия ответа. Для изменяемого номера назначения допускается AstDB. Не допускайте переадресации на исходный номер и иных циклов. Объясните выбор по DIALSTATUS.

*Пример 6 — получение результата Dial()*

```text
same => n,Dial(PJSIP/1101,12)
same => n,NoOp(Статус: ${DIALSTATUS})
```

Само условие ветвления по статусу реализуйте самостоятельно.

### 4.6. Конференц-связь

В confbridge.conf подготовьте профили конференции и пользователей. Создайте точку входа ConfBridge(), подключите не менее трёх клиентов, проверьте слышимость каждого и выход участника. Для варианта с PIN проверьте отказ при неправильном PIN.

*Пример 7 — подключение к комнате*

```text
exten => 0994,1,Answer()
 same => n,ConfBridge(7001)
 same => n,Hangup()
```

### 4.7. Маршрутизация по расписанию

Настройте GotoIfTime() с разными действиями для рабочего и нерабочего периода. Сверьте часовой пояс Ubuntu с ожидаемым расписанием. Продемонстрируйте оба исхода, включая проверку пограничного времени.

*Пример 8 — развилка по времени*

```text
exten => 0995,1,GotoIfTime(09:00-17:59,mon-fri,*,*?work)
 same => n,Goto(closed)
 same => n(work),NoOp(Рабочий период)
 same => n,Hangup()
 same => n(closed),NoOp(Нерабочий период)
 same => n,Hangup()
```

### 4.8. Парковка и перехват

Проверьте наличие res_parking и настройки res_parking.conf. Создайте диапазон парковочных слотов, припаркуйте тестовый разговор и получите его с другого телефона. Отдельно проверьте перехват ещё не отвеченного вызова, настроив pickupgroup/callgroup у нужных PJSIP endpoint. Отличайте эти механизмы по этапу вызова и поведению каналов.

### 4.9. Запись разговоров

Настройте MixMonitor() для согласованного тестового разговора. Создавайте имена из безопасного идентификатора UNIQUEID; не подставляйте недоверенные значения CallerID в путь. Проверьте права на каталог и реальное содержимое полученной записи.

*Пример 9 — запись соединённого разговора*

```text
same => n,MixMonitor(${UNIQUEID}.wav,b)
same => n,Dial(PJSIP/1101,20)
same => n,StopMixMonitor()
```

Опция b ограничивает запись временем соединения каналов; если требуется использовать файл до завершения канала, нужна StopMixMonitor().

### 4.10. Фильтрация вызовов и DND

Создайте правило чёрного списка тестовых идентификаторов и переключаемый режим «не беспокоить» для одного абонента. Храните состояние DND в AstDB, проверяйте его до Dial(), обеспечьте служебный номер управления и корректный маршрут отказа. CallerID может быть подменён, поэтому такое правило не заменяет SIP-аутентификацию.

*Пример 10 — чтение состояния DND*

```text
same => n,NoOp(DND=${DB(dnd/1101)})
```

### 4.11. Применение изменений и диагностика

После редактирования extensions.conf выполните dialplan reload; для конфигураций приложений применяйте соответствующую команду reload и проверяйте фактическую загрузку. Если команда отсутствует, проверьте модуль. При неудаче восстановите сохранённый вариант файла, не обрывая рабочие вызовы без необходимости.

*Пример 11 — команды CLI*

```text
dialplan reload
core show channels verbose
queue show
confbridge list
parking show
```
